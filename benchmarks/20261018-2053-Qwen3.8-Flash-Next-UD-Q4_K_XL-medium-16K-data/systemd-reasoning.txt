The differences between manual root execution and systemd execution:
1. **User/identity**: Even if User=root is in the unit file, systemd might run with different UID/GID context, supplementary groups, or capabilities. If no User= is specified, it defaults to root, but the security context differs.
2. **Environment**: systemd strips most environment variables. No PATH, no LD_LIBRARY_PATH, no JAVA_HOME, etc. The shell profile is not sourced.
3. **Working directory**: systemd uses / as default WorkingDirectory unless specified. The app might depend on relative paths.
4. **Permissions**: File access, file descriptor limits, capability drops.
5. **SELinux**: RHEL enforces SELinux by default. Manual execution inherits the user's SELinux context (unconfined_t for root), but systemd runs services in a specific domain (or unconfined_service_t / custom domain).
6. **Dependencies**: After=, Requires=, Wants= — services might depend on network, mounts, etc. that aren't ready.
7. **Filesystem paths**: Absolute vs relative paths. systemd doesn't resolve paths the same way a shell does.
8. **Journal logs**: systemctl status, journalctl -u, dmesg.
